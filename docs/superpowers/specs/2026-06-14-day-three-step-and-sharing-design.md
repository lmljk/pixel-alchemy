# 第三天单步与分享存档设计

## 目标

第三天在八种材料沙盒上补齐两个可展示能力：

1. 暂停时可以逐步观察一次材料更新。
2. 可以把当前完整画布复制为链接；接收者打开后看到同一画面，并从同一随机状态继续演化。

整个方案保持纯前端运行，不新增 API Key、服务器、数据库、登录、上传、浏览器文件权限或网络依赖。

## 第三天范围

### 包含

- 暂停状态下的单步按钮
- 可保存与恢复内部状态的确定性随机数生成器
- 当前网格和下一次随机状态的版本化存档
- URL 哈希中的分享链接
- 自动复制分享链接和短暂状态提示
- 分享链接校验及安全回退
- 页面阶段标签更新为“试验 03”
- 桌面和手机浏览器验收

### 不包含

- 短链接服务
- 云端作品库
- 用户账号
- 分享预览图
- 二维码
- 手动编辑种子
- 撤销、重做或时间轴
- 跨未来规则版本保证完全一致

## 用户行为

### 单步

- “单步”按钮只在模拟暂停时启用。
- 每次点击严格调用一次 `Simulation.step()`。
- 单步后保持暂停，不自动继续。
- 运行时按钮为原生 `disabled`，避免同时发生自动帧和手动帧。
- 暂停期间仍可绘制、擦除、清空和分享。

### 分享

- 点击“分享”时读取当前网格和随机数生成器的下一步状态。
- 应用生成当前页面的 `#share=<payload>` 链接并写入剪贴板。
- 复制成功后按钮短暂显示“已复制”。
- 复制失败时显示“复制失败”，画布和当前 URL 均不改变。
- 生成链接时不修改当前标签页的哈希，避免制造额外历史记录或重新初始化应用。
- 打开有效分享链接时恢复完整画布，并始终以暂停状态开始。
- 恢复后的画布执行相同数量的单步，必须与分享来源产生完全相同的网格。

## 状态所有权

`App` 创建并持有本次会话唯一的 `Simulation` 实例，再把它传给 `SandboxCanvas`。这样分享按钮可以在用户点击的同一个 JavaScript 任务中读取一致快照，而不需要从 Canvas 反向复制 React 状态。

`App` 继续持有：

- 当前材料
- 暂停状态
- 清空版本号
- 单步版本号
- 分享提示
- 初始分享链接解析错误

`SandboxCanvas` 继续负责动画循环、绘制输入和渲染。它监听单步版本号；版本变化且当前处于暂停状态时调用一次 `step()`。组件首次挂载时只记录版本，不隐式推进。

`Simulation` 提供只读快照，包含网格副本和下一步扫描方向；恢复构造参数可以装入这两项状态。扫描方向必须进入分享存档，因为相同网格和随机状态若使用不同扫描方向，材料争抢同一空位时仍可能产生不同结果。

## 确定性随机源

新增一个小型 `SeededRandom` 实现，使用固定的 32 位 `mulberry32` 算法：

- 状态是无符号 32 位整数。
- `next()` 每次先推进状态，再返回 `[0, 1)` 浮点数。
- `getState()` 返回下一次调用前的内部状态。
- 从相同状态恢复后，后续随机序列完全一致。

生产环境不再把 `Math.random` 直接传给 Simulation。新会话优先使用 `crypto.getRandomValues` 生成初始状态；测试和不支持该 API 的环境使用显式种子或时间回退。

`Simulation` 仍允许测试注入普通随机函数，保留第二天已有的确定性规则测试。只有带状态的生产随机源才能导出分享存档；应用创建路径保证这一条件成立。

渲染颜色继续只依赖网格索引和材料编号，不消耗模拟随机序列。

## 存档格式

分享链接使用：

```text
#share=<base64url payload>
```

载荷为版本化二进制数据：

| 字节 | 内容 |
| --- | --- |
| `0` | 格式版本，第三天固定为 `1` |
| `1..2` | 网格宽度，无符号 16 位大端序 |
| `3..4` | 网格高度，无符号 16 位大端序 |
| `5..8` | PRNG 状态，无符号 32 位大端序 |
| `9` | 标志位；bit 0 表示下一步从左向右扫描，其余位必须为零 |
| `10..` | RLE 数据，每组为材料编号 `uint8` + 连续长度 `uint16` |

RLE 按 `cells` 的行优先顺序编码。连续长度必须在 `1..65535`，同材料超长段拆成多组。编码完成后使用 URL 安全 Base64：`+` 替换为 `-`，`/` 替换为 `_`，移除末尾 `=`。

版本号同时锁定材料编号、扫描规则和 PRNG 算法。未来规则发生不兼容变化时增加版本，而不是静默误读旧链接。

## 解码与错误处理

解析分享链接时依次校验：

1. 哈希是否以 `#share=` 开头且载荷非空。
2. Base64url 字符和补位是否合法。
3. 载荷至少包含 10 字节头部。
4. 格式版本是否为 `1`。
5. 宽高是否均在 `1..160`，且总单元数与两者乘积一致。
6. 标志位是否只使用已定义的 bit 0。
7. 每组 RLE 是否完整，长度是否非零。
8. 材料编号是否在 `Material.Empty..Material.Plant` 范围内。
9. 所有连续段之和是否严格等于宽高乘积。

无分享哈希时创建正常的 `160 × 160` 空白模拟。分享哈希无效时也创建空白模拟，但页面显示“分享链接无效，已打开空白画布”。解析失败不得抛出到 React 根节点，也不得部分载入损坏数据。

第三天只接受宽和高均不超过 `160` 的分享网格，避免恶意链接申请过大内存或创建极端纵横比 Canvas。有效分享可保留载荷中的实际宽高，便于单元测试和格式演进。

## 剪贴板行为

分享使用标准 `navigator.clipboard.writeText`。该 API 通常要求 HTTPS 或 localhost，并可能被浏览器策略拒绝：

- 成功：提示“已复制”，约两秒后恢复“分享”。
- 失败或 API 不存在：提示“复制失败”，并保留当前画布。
- 调用超过 `1.5` 秒仍未结束时按失败处理，避免浏览器剪贴板实现悬挂后界面永久无反馈。
- 不弹出权限请求之外的模态框，不使用已弃用的 `document.execCommand`。

部署到普通 HTTP 地址时复制可能失败，这是浏览器安全限制；应用本身仍可正常运行，但分享功能需要 HTTPS 或 localhost。

## 界面

页面结构保持第二天风格：

1. 标题与“试验 03”
2. Canvas
3. 横向可滚动材料栏
4. 操作栏：暂停或继续、单步、清空、分享
5. 可访问的状态提示区域

操作栏允许在窄屏换行，不造成页面整体横向溢出。所有按钮高度继续不小于 `44px`。分享状态使用 `aria-live="polite"`，无效链接错误使用 `role="status"`，不依赖颜色传达。

## 测试策略

### 随机源

- 相同初始状态产生相同序列。
- 不同状态产生不同序列。
- 保存状态后恢复，后续序列完全相同。
- 所有值位于 `[0, 1)`。

### 存档编解码

- 空白、单材料和混合材料网格可往返恢复。
- 宽高、所有网格字节、PRNG 状态和下一步扫描方向严格相等。
- Base64url 结果不包含 `+`、`/` 或 `=`。
- 拒绝未知版本、非法材料、零长度段、截断数据、尺寸超限和总长度不匹配。

### 单步

- 运行时“单步”禁用。
- 暂停时点击一次只推进一次。
- 连续点击两次推进两次并保持暂停。
- 初次挂载和切换暂停不会自动推进。

### 分享

- 点击分享将包含 `#share=` 的当前状态链接写入剪贴板。
- 复制成功显示“已复制”。
- 剪贴板拒绝时显示“复制失败”，应用不崩溃。
- 剪贴板 Promise 不结束时在超时后显示“复制失败”。
- 有效分享链接恢复网格并默认暂停。
- 两个从同一存档恢复的模拟执行相同步数后网格完全相等。
- 无效分享链接回退为空白模拟并显示错误。

### 回归与浏览器验收

- 八种材料、橡皮、暂停、继续和清空继续工作。
- 在暂停状态画出可辨认场景，单步可观察材料只推进一次。
- 复制链接，在新页面打开后画面一致且默认暂停。
- 来源和恢复页面分别单步相同次数后画面一致。
- 桌面与 `390 × 844` 手机视口无整体横向溢出。
- 手机操作按钮完整可用，材料栏仍可横向滚动。
- 控制台无相关错误或警告。

## 第三天完成标准

- 单步严格一次推进且只能在暂停时使用。
- 分享链接恢复当前完整画布与下一步随机轨迹。
- 分享恢复后默认暂停。
- 损坏链接和剪贴板失败均有清晰、非破坏性反馈。
- 全量测试和生产构建通过。
- 桌面与手机浏览器核心流程通过。
- 没有引入后端、数据库、第三方运行时服务或新浏览器权限。
