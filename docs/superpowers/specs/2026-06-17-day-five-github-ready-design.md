# 第五天 GitHub 发布准备设计

## 目标

第五天把当前像素炼金术 demo 打磨成可以提交到 GitHub 的项目形态。重点不是继续扩展物理规则，而是让第一次打开仓库或页面的人知道这是什么、怎么运行、怎么玩、当前有哪些限制。

本阶段完成后，项目应当可以：

1. 作为 GitHub 仓库被别人阅读。
2. 在本地用 README 跑起来。
3. 打开应用后快速理解操作方式和材料效果。
4. 通过测试和构建验证当前 demo 可交付。

## 第五天范围

### 包含

- 新增 `README.md`
  - 项目简介
  - 功能清单
  - 本地运行命令
  - 材料说明
  - 分享链接说明
  - 已知限制
  - Sandspiel 参考说明
- 应用内新增轻量上手说明
  - 告诉用户可以画材料、暂停、单步、清空、分享
  - 简述三种最有趣的新材料：蒸汽、熔岩、酸液
  - 不遮挡画布，不引入复杂教程流程
- 页面阶段标签更新为“试验 05”
- 更新或新增测试覆盖第五天文案
- 通过全量测试和生产构建
- 准备 GitHub 发布流程

### 不包含

- 新物理材料
- 新模拟规则
- 云端保存、账号、作品库或后端
- 部署到 Vercel、GitHub Pages 或其他平台
- 复杂截图生成流程
- 大型 UI 重设计
- 兼容旧 `v1` 分享链接

## 应用内说明设计

在标题和画布之间加入一个短说明区。说明区使用现有纸张风格，不新增弹窗或可关闭状态。

文案保持简短：

- 第一行说明玩法：“选择材料，在画布上绘制；暂停后可单步观察。”
- 第二行说明亮点：“熔岩遇水成石并产蒸汽，酸液会腐蚀墙、石头、木头和植物。”
- 第三行说明分享：“分享会复制当前画布和随机状态；需要 HTTPS 或 localhost 剪贴板权限。”

说明区需要满足：

- 桌面和手机都不造成横向溢出。
- 不抢走 Canvas 的视觉主位。
- 使用普通文本，可被屏幕阅读器读取。

## README 设计

`README.md` 面向第一次进入 GitHub 仓库的人，结构为：

1. 标题：像素炼金术
2. 简介：一个受 Sandspiel 启发的纯前端像素物理沙盒
3. 当前功能：
   - 11 种材料和橡皮
   - 画笔绘制
   - 暂停、单步、清空
   - URL 分享当前画布和随机状态
4. 快速开始：
   - `npm ci`
   - `npm run dev`
   - `npm test`
   - `npm run build`
5. 材料表：
   - 沙子、水、墙、石头、木头、油、火、植物、蒸汽、熔岩、酸液
6. 分享链接限制：
   - 当前格式为 `v2`
   - 旧 `v1` 链接会安全回退为空白画布
   - 剪贴板需要 HTTPS 或 localhost
7. 项目来源：
   - 参考 Sandspiel 的核心体验
   - 当前实现是轻量独立版本
8. 开发计划：
   - 未来可加笔刷大小、移动端手势优化、更多材料、部署

README 不承诺已经上线，不写不存在的线上地址。

## GitHub 发布流程

当前本地仓库还没有 remote，`gh auth status` 显示账号 `lmljk` 的 token 失效。第五天实现可以先在本地完成并提交；推送 GitHub 时需要先解决：

1. 用户重新登录 GitHub CLI：`gh auth login -h github.com`
2. 确认目标仓库：
   - 若用户已有仓库，添加为 `origin`
   - 若用户没有仓库，用 `gh repo create` 创建
3. 推送 `codex/day-five-github-ready`
4. 创建 draft PR，或在用户确认时推送到目标默认分支

在 GitHub 认证恢复前，不尝试猜测远端地址，也不伪造发布完成状态。
